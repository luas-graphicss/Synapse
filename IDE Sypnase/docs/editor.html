Editor de código

O editor da Synapse não usa um componente de terceiros. Ele tem tokenizador próprio, serviço de sugestões em worker separado e formatador integrado. Esta página explica o que cada parte cobre e onde ela para.

revisado em 09/09/2026 leitura 11 min público: dev

Linguagens reconhecidas

A linguagem é escolhida pela extensão do arquivo. Cada linguagem tem uma gramática própria para o realce e um conjunto de regras de indentação.

Linguagem Extensões
JavaScript js mjs cjs jsx
TypeScript ts tsx mts cts
HTML e marcação html htm xml svg vue svelte
CSS css scss less
JSON json jsonc webmanifest

Arquivos com extensão desconhecida abrem como texto simples. O realce fica desligado, mas edição, busca e gravação continuam normais.

Sugestões e IntelliSense

As sugestões vêm de duas fontes. A primeira é a análise local do arquivo, que coleta símbolos declarados, propriedades usadas e palavras do próprio documento. A segunda é o serviço de linguagem que roda em worker, fora da thread da interface, para não travar a digitação.

  • A lista abre sozinha enquanto você digita identificadores.
  • Mod+Space força a abertura, útil depois de um ponto ou dentro de string.
  • Enter ou Tab aceitam, Esc descarta.
  • Em HTML e CSS a lista também cobre tags, atributos e propriedades conhecidas.

A sugestão não substitui um projeto TypeScript completo. Ela não resolve tipos vindos de dependências instaladas no disco, só o que está dentro do projeto aberto.

Diagnósticos

Erros de sintaxe aparecem sublinhados na linha e listados no painel de build. Cada gravação roda uma validação rápida do arquivo salvo, e o resultado diz se o arquivo quebrou.

Detalhe importante

O arquivo é gravado mesmo com erro de sintaxe. A IDE avisa em vez de bloquear, para você não perder o que digitou. Corrija antes de continuar, porque o preview vai falhar ao carregar aquele módulo.

Diagnósticos de tipo, quando disponíveis, aparecem em cinza e não impedem execução. Diagnósticos de sintaxe aparecem em vermelho.

Formatação

Alt+Shift+F formata o arquivo ativo. A formatação respeita a linguagem detectada e mantém a posição do cursor sempre que possível.

Para formatar vários arquivos, use a ação de formatar projeto pela paleta. Ela mostra progresso e pode ser interrompida no meio sem deixar arquivo pela metade.

Busca e substituição

Ação Atalho Escopo
Localizar Mod+F Arquivo ativo
Substituir Mod+Shift+H Arquivo ativo
Localizar no projeto Mod+Shift+F Todos os arquivos de texto

A busca no projeto ignora binários e pastas de dependência. Os resultados são agrupados por arquivo e cada linha leva direto para a posição exata.

Navegação entre símbolos

O editor mantém um mapa de funções, classes e blocos de cada arquivo aberto. Esse mapa alimenta a lista de símbolos, o salto para definição e o breadcrumb acima do código. Em arquivos grandes, prefira o mapa à rolagem manual.

Arquivos grandes

Acima de aproximadamente 250 mil caracteres ou 7 mil linhas, o editor entra em modo reduzido: realce de sintaxe e análise pesada saem de cena e sobra edição de texto puro. É proposital, para a rolagem continuar utilizável.

Se você trabalha sempre com arquivos desse tamanho, vale quebrá-los em módulos menores. Isso melhora também o tempo de recompilação do preview.

Limites atuais

  • Sem renomeação de símbolo em vários arquivos de uma vez.
  • Sem suporte a linguagens de backend com realce dedicado.
  • Múltiplos cursores cobrem seleção vertical, mas não seleção por padrão regex.

Se o editor se comportou diferente do descrito aqui, mande o trecho de código junto no relato de bug.
