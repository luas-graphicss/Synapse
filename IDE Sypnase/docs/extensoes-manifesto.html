Extensões / Manifesto e permissões

O manifesto synapse-extension.json

Cada campo do manifesto, o que ele libera, o que ele restringe e como a IDE valida tudo antes de ativar a extensão. Com o JSON Schema oficial para autocompletar no editor.

revisado em 15/09/2026 leitura 9 min público: dev

Estrutura mínima

{
	"$schema": "https://sypnase-live-preview.vercel.app/schemas/extension-manifest.schema.json",
	"id": "ana.hello-world",
	"name": "Hello World",
	"version": "1.0.0",
	"publisher": "ana",
	"main": "extension.js",
	"engines": { "synapse": "^2.4.0" },
	"activationEvents": ["onCommand:hello.dizerOla"],
	"permissions": ["editor"],
	"contributes": {
		"commands": [{ "command": "hello.dizerOla", "title": "Hello: Dizer olá" }]
	}
}

Cinco campos são obrigatórios: id, name, version, publisher e main. O resto é opcional, mas quase toda extensão útil declara activationEvents, permissions e contributes.

Autocompletar no editor Aponte $schema para o arquivo acima (ou para ../../schemas/extension-manifest.schema.json em repositórios locais). A IDE, o VS Code e qualquer editor com suporte a JSON Schema passam a sugerir campos e apontar erros enquanto você digita.

Identidade

id
Formato publisher.nome, tudo em minúsculas, números e hífens. É a chave usada em configurações, comandos internos e no registro de pacotes. Não muda depois de publicado.
name
Nome de exibição, até 80 caracteres.
version
Semver estrito (1.2.3, 1.2.3-beta.1). A IDE compara versões para decidir atualização e rollback.
publisher
Precisa ser igual ao prefixo do id.
icon
Caminho relativo de uma imagem PNG, JPG, WebP ou SVG dentro do pacote (ex.: media/icon.png). Quadrada, de 128 a 256 px, até 512 KB. Aparece na view de Extensões, na página de detalhes e no marketplace; sem ela a IDE mostra as iniciais do nome. O assistente Extensões: Criar nova extensão… pede a imagem ao criar o projeto, e Extensões: Definir ícone da extensão… troca depois.
description, categories, repository, license
Metadados de vitrine. categories aceita: Linguagens, Temas, Formatadores, Snippets, Depuradores, Outros.
engines.synapse
Faixa semver da API exigida. Se a IDE for mais antiga que o mínimo, a extensão fica em estado incompatible e não ativa. A versão atual está em synapse.version e no topo da referência.

Eventos de ativação

activationEvents controla quando o worker é criado. Menos eventos, IDE mais leve. Se omitido, vale * (ativa na inicialização).

EventoAtiva quando
onStartupFinishedA IDE terminou de carregar e ficou ociosa.
onCommand:<id>Alguém executa o comando pela primeira vez (paleta, atalho, menu, outra extensão).
onLanguage:<id>Um arquivo da linguagem é aberto no editor.
onView:<id>A view contribuída fica visível pela primeira vez.
workspaceContains:<glob>O projeto aberto tem um arquivo que casa com o padrão (ex.: **/Cargo.toml).
*Imediatamente. Evite; reserve para temas e coisas que precisam existir antes de tudo.

Permissões

Toda chamada de API que sai do worker passa por uma checagem de permissão. Uma extensão sem a permissão certa recebe PermissionDenied e o evento aparece no painel de auditoria. O usuário vê a lista completa antes de instalar.

PermissãoLibera
editorsynapse.window.activeTextEditor, seleções, decorações, edições no documento aberto, status bar, mensagens e quick pick.
workspace.readLer arquivos e metadados do projeto ativo, eventos de mudança e watchers.
workspace.writeCriar, alterar, renomear e apagar arquivos do projeto ativo. Implica workspace.read. Toda gravação entra na pilha de desfazer da IDE.
workspace.allO mesmo que workspace.write, mas para todos os projetos abertos. Necessária para synapse.workspace.projects.
webviewcreateWebviewPanel e registerWebviewViewProvider.
clipboardsynapse.env.clipboard.
previewInjetar scripts, recarregar, mudar viewport e ler o estado do preview.
mcpExpor ferramentas para agentes conectados pela ponte MCP.
network:https://<host>fetch para exatamente aquele host. Uma entrada por host; sem coringa.
Workspaces não confiáveis Declare capabilities.untrustedWorkspaces.supported como true, false ou "limited". Em projeto não confiável, extensões com false não ativam; com "limited" ativam sem workspace.write, preview e network:*.

Contribuições

contributes é declarativo: a IDE lê e registra tudo isso antes de ativar o worker, por isso comandos aparecem na paleta e atalhos funcionam mesmo com a extensão dormindo.

commands[]
command, title, opcionais category e icon. O código precisa registrar o mesmo id com synapse.commands.registerCommand.
keybindings[]
command, key (ex.: ctrl+alt+m), opcionais mac e when. Conflitos com atalhos do usuário são resolvidos a favor do usuário.
menus
Objeto com editor/context, explorer/context e commandPalette, cada um com { command, when, group }.
languages[]
id, extensions, aliases, filenames, configuration (comentários, pares de fechamento).
grammars[]
language + path para o JSON da gramática. Veja Linguagens.
themes[] e iconThemes[]
label, uiTheme (dark/light) e path.
snippets[]
language + path no formato { "nome": { "prefix", "body", "description" } }.
configuration
title e properties no formato JSON Schema reduzido; aparecem na tela de configurações da IDE e são lidas com synapse.workspace.getConfiguration.
views.sidebar[]
id, name, opcionais icon e when. Preenchidas por registerWebviewViewProvider.
statusBar[]
Itens estáticos: id, alignment, priority, text, tooltip, command.

Localização do manifesto

Qualquer string de exibição aceita a forma %chave%. A IDE procura package.nls.json (padrão) e package.nls.<idioma>.json na pasta da extensão e substitui de acordo com o idioma ativo. 

// synapse-extension.json
"contributes": { "commands": [{ "command": "x.run", "title": "%cmd.run%" }] }

// package.nls.json
{ "cmd.run": "Run analysis" }

// package.nls.pt-br.json
{ "cmd.run": "Executar análise" }

Como a validação acontece

  1. JSON precisa fazer parse. Erro de sintaxe bloqueia tudo.
  2. Cada campo é checado contra tipo, padrão, tamanho e enumeração. Os erros vêm com o caminho (contributes.commands[2].title) e uma dica.
  3. main, icon e todos os path precisam existir na pasta.
  4. Comandos declarados em keybindings, menus e statusBar precisam existir em contributes.commands.
  5. engines.synapse é comparado com synapse.version.

Você vê o resultado no console da IDE ao executar a pasta, no Extension Development Host e ao empacotar. A mesma rotina roda na instalação de um .sx.

O validador da IDE e o JSON Schema em schemas/extension-manifest.schema.json usam as mesmas regras; se um aceita, o outro aceita.
