Terminal e relay

O navegador não executa processos do sistema. Para rodar npm, node ou um build de verdade, a IDE fala com um processo local chamado relay, que trabalha numa pasta espelhada do projeto.

revisado em 09/09/2026 leitura 9 min público: dev

O que o relay faz

  • Mantém uma cópia do projeto em disco, sincronizada a cada gravação.
  • Executa comandos nessa pasta e devolve a saída em tempo real.
  • Sobe o dev server e vira proxy para o preview.
  • Traz de volta arquivos gerados por ferramentas externas.

Sem relay, a IDE segue útil para editar e ver preview interno. O que fica indisponível é tudo que exige processo de sistema.

Permissão de terminal

Execução de comandos vem desligada. Você precisa marcar a permissão de terminal no menu de integrações antes da primeira execução. Essa é uma barreira intencional: comando executado no relay tem o mesmo poder de um comando digitado no seu terminal.

Segurança

Nunca deixe a permissão de terminal ligada com um projeto de origem desconhecida aberto. Scripts do projeto podem ser executados por ações automatizadas.

Comandos longos

Comandos que não terminam rápido continuam rodando em segundo plano e recebem um identificador de processo. Você acompanha a saída por esse identificador e encerra quando quiser. 

npm install
npm run build
node scripts/gerar-assets.js

Processos que ficam vivos por natureza, como servidores e observadores de arquivo, devem ser iniciados como serviço e não como comando comum, senão o painel fica preso esperando o fim.

Dev server

  1. Instale as dependências com npm install.
  2. Inicie o servidor, normalmente npm run dev.
  3. Aguarde a porta ser detectada na saída do comando.
  4. O preview passa a mostrar o dev server, com recarga automática.

Se a porta não aparecer sozinha, consulte o estado do dev server: ele informa porta, situação e as últimas linhas de log. Encerre o servidor antes de trocar de projeto para não deixar processo órfão.

Sincronização com o disco

Gravações feitas na IDE descem para a pasta espelhada. O caminho inverso também existe: arquivos criados por comandos voltam para a IDE e para o preview.

Editar o mesmo arquivo ao mesmo tempo na IDE e num editor externo pode gerar conflito. Escolha um lado por vez.

Quando o relay cai

A IDE detecta a queda e marca as ferramentas dependentes como indisponíveis. O projeto em si não é afetado, porque a fonte da verdade continua no armazenamento do navegador. Religue o relay e a sincronização retoma do ponto atual.

Sintomas típicos de relay fora do ar: terminal sem resposta, dev server inacessível e build parando na preparação do ambiente.

Problema com comando específico? Inclua o comando exato e a saída completa no relato.
