Preview ao vivo

O preview é o coração do ciclo de trabalho na Synapse. Ele monta o projeto na hora, roda dentro de um iframe isolado e devolve console, erros e requisições para a IDE.

revisado em 09/09/2026 leitura 10 min público: dev

Como o preview é montado

Quando o projeto não tem dev server, a IDE trabalha em modo interno. Ela lê a árvore de arquivos em memória, gera endereços temporários para cada recurso e reescreve as referências do HTML para apontar para esses endereços. O resultado é injetado no iframe.

  1. Encontrar o ponto de entrada HTML.
  2. Resolver script, link, imagens e mídias do projeto.
  3. Publicar cada arquivo num endereço temporário da própria sessão.
  4. Injetar o documento final e ligar a captura de console e de erros.

Importações entre módulos ES continuam funcionando porque os caminhos relativos também são reescritos. Import de pacote instalado, sem caminho relativo, não funciona no modo interno: para isso use dev server.

Quando ele atualiza

Evento Efeito
Gravação de arquivo Remontagem agrupada, para várias gravações seguidas gerarem um refresh.
Somente CSS mudou Troca de folha de estilo sem recarregar o documento.
Arquivo criado ou removido Remontagem completa.
Mod+S Força a remontagem imediata.
Por que agrupar

Sem agrupamento, digitar rápido em três arquivos dispararia três montagens e o preview piscaria sem parar. A IDE espera a rajada terminar antes de remontar.

Console e erros

A IDE intercepta as chamadas de console dentro do iframe e também escuta erros não tratados e promessas rejeitadas. Cada linha guarda origem, nível e horário.

  • Erros de sintaxe aparecem antes de qualquer log do seu código.
  • Erro de recurso ausente aparece como falha de carregamento, não como exceção.
  • O painel guarda um limite de linhas e descarta as mais antigas.

Se o console fica vazio depois de uma mudança que deveria logar algo, quase sempre o módulo não chegou a executar. Procure a primeira linha vermelha e resolva ela primeiro.

Rede

O registro de rede lista fetch, XHR e recursos estáticos com status e tempo. Ele é o lugar certo quando uma imagem não aparece ou uma API responde diferente do esperado.

Requisições para domínios externos seguem as regras de CORS do navegador. O preview não contorna isso: é uma limitação da plataforma e não da IDE.

Tamanho de tela

O preview aceita tamanhos fixos para testar layout responsivo, com presets de celular, tablet, notebook e desktop, além de largura e altura manuais. A densidade de pixel também pode ser emulada.

Valores usados com frequência: 390 por 844 para celular, 820 por 1180 para tablet e 1920 por 1080 para desktop. Volte para o tamanho padrão antes de medir desempenho, porque o viewport reduzido altera o custo de renderização.

Estado do aplicativo

O preview compartilha armazenamento com a sessão anterior do seu app. Se você está testando fluxo de primeiro acesso, limpe o estado antes: isso apaga localStorage, sessionStorage, bases IndexedDB e caches do app e recarrega o preview.

Atenção

Limpar o estado do preview apaga dados do app em teste, não os arquivos do projeto. Mesmo assim, se o seu app guarda algo que você quer manter, exporte antes.

Preview com dev server

Projetos com build real trocam o modo interno pelo servidor de desenvolvimento. O relay funciona como proxy e o preview passa a mostrar exatamente o que o dev server serve, com recarga automática própria da ferramenta.

Nesse modo, as ferramentas de inspeção continuam valendo: console, rede, captura de tela e execução de expressões. O passo a passo está em Terminal e relay.

Preview em branco ou congelado? Copie as linhas do console no relato de bug, ajuda muito.
