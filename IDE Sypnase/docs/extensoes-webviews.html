Extensões / Webviews

Webviews: painéis com HTML próprio

Como abrir um painel no editor ou uma view na barra lateral com HTML seu, trocar mensagens com a extensão, herdar o tema da IDE e respeitar a política de segurança que o host impõe.

revisado em 15/09/2026 leitura 8 min público: dev

Dois formatos

Painel (WebviewPanel)
Ocupa uma aba do editor. Criado sob demanda com synapse.window.createWebviewPanel. Ideal para relatórios, dashboards, editores visuais.
View (WebviewView)
Vive na barra lateral, declarada em contributes.views.sidebar e preenchida por registerWebviewViewProvider. Ideal para listas, ferramentas de contexto, coisas sempre visíveis.

Ambos exigem a permissão webview no manifesto.

Abrindo um painel

const painel = synapse.window.createWebviewPanel(
	'minhaext.relatorio',
	'Relatório',
	synapse.ViewColumn.Active,
	{ enableScripts: true, retainContextWhenHidden: true },
);

painel.webview.html = montarHtml(painel.webview);

painel.webview.onDidReceiveMessage((mensagem) => {
	if (mensagem.type === 'copiar') synapse.env.clipboard.writeText(mensagem.texto);
});

painel.onDidDispose(() => limparRecursos());
context.subscriptions.push(painel);
enableScripts
Padrão true. Desligue para conteúdo puramente estático.
retainContextWhenHidden
Padrão true. Com false o iframe é descarregado quando a aba perde o foco e o estado JS some; use getState/setState para sobreviver.

CSP e o nonce

O host renderiza seu HTML em um iframe isolado com uma Content-Security-Policy que só executa scripts marcados com o nonce daquela renderização. Você recebe o nonce em webview.nonce e a fonte pronta em webview.cspSource. 

function montarHtml(webview) {
	return `<!DOCTYPE html>
<html lang="pt-BR">
<head>
	<meta charset="utf-8" />
	<meta http-equiv="Content-Security-Policy"
		content="default-src 'none'; style-src ${webview.cspSource} 'unsafe-inline'; script-src ${webview.cspSource}; img-src data:;" />
</head>
<body class="sx-pad">
	<button class="sx-btn primary" id="ok">Confirmar</button>
	<script nonce="${webview.nonce}">
		const api = acquireSynapseApi();
		document.getElementById('ok').addEventListener('click', () => api.postMessage({ type: 'ok' }));
	</script>
</body>
</html>`;
}
O que não funciona onclick="...", javascript: em links, eval, scripts externos por URL e fetch para fora. A webview não tem rede; peça à extensão (que pode ter network:https://host) e receba por mensagem.

A API dentro da webview

acquireSynapseApi() só pode ser chamada uma vez por documento e devolve:

postMessage(dados)
Envia para webview.onDidReceiveMessage na extensão. Só JSON serializável.
getState() / setState(estado)
Persistem um objeto pequeno enquanto o painel existe, mesmo com retainContextWhenHidden: false.

No sentido contrário, a extensão chama webview.postMessage(dados) e a webview escuta com window.addEventListener('message', (e) => e.data).

Tema e kit de estilos

O host injeta automaticamente as variáveis --synapse-* (fundo, texto, acento, bordas, fontes) e um kit de classes utilitárias com prefixo sx-, por isso um painel simples nem precisa de CSS próprio.

ClasseUso
sx-pad, sx-stack, sx-row, sx-growEspaçamento e layout em coluna/linha.
sx-btn (+ primary, sm)Botões no estilo da IDE.
sx-list, sx-list-item, sx-emptyListas clicáveis e estado vazio.
sx-label, sx-meta, sx-hint, sx-monoTipografia secundária e monoespaçada.
sx-badge (+ acc), sx-swatchContadores e amostras de cor.

Quando o usuário troca de tema, a webview recebe a mensagem { type: 'synapse:theme', kind: 'dark' | 'light' } e as variáveis são atualizadas sem recarregar.

View na barra lateral

// manifesto
"contributes": { "views": { "sidebar": [{ "id": "minhaext.cores", "name": "Cores", "icon": "palette" }] } },
"activationEvents": ["onView:minhaext.cores"]

// extension.js
synapse.window.registerWebviewViewProvider('minhaext.cores', {
	resolveWebviewView(view) {
		view.webview.options = { enableScripts: true };
		view.webview.html = montarHtml(view.webview);
		view.onDidChangeVisibility(() => view.visible && atualizar(view.webview));
	},
});

Depurando

  • Erros de script dentro da webview aparecem no Console do Extension Development Host com o prefixo [webview].
  • Violações de CSP aparecem como Refused to execute inline script; confira o nonce.
  • O Inspetor mostra quantos painéis e views a extensão tem abertos.
  • Exemplo completo: exemplos/extensoes/paleta-de-cores.

Webview em branco? Quase sempre é script sem nonce ou HTML montado antes de o painel existir.
