Synapse IDE

A Synapse é um ambiente de desenvolvimento que roda inteiro no navegador: editor, preview ao vivo, build, terminal ligado ao seu disco, Blepse 3D e uma ponte para agentes externos. Esta documentação explica como cada parte funciona, o que esperar dela e onde olhar quando algo dá errado.

revisado em 09/09/2026 leitura 7 min público: todos

O que a Synapse é

A IDE foi feita para projetos web que precisam de retorno imediato. Você edita um arquivo e o preview atualiza sem passar por servidor de build remoto. Nada do seu código precisa sair da máquina para o editor funcionar: o projeto vive no armazenamento do navegador e, quando você liga o relay, também numa pasta espelhada no disco.

Ela não tenta ser um editor genérico com mil plugins. O foco é um ciclo curto de escrever, ver rodando, medir e corrigir, com ferramentas de build e de 3D no mesmo lugar.

Para quem esta documentação serve

  • Quem está começando e quer sair do zero até um projeto rodando em poucos minutos.
  • Quem quer estudar a engine por dentro: como o preview é montado, como o build resolve módulos, como os agentes escrevem no projeto.
  • Quem esbarrou num comportamento estranho e quer confirmar se é bug, limite conhecido ou configuração.

Como a IDE está organizada por dentro

O código é dividido em camadas independentes. Cada camada conversa com a vizinha por uma superfície pequena, o que permite trocar uma parte sem quebrar as outras.

núcleo
Estado do projeto em memória, lista de arquivos, arquivo ativo e eventos que o resto da IDE escuta.
sincronização
Gravação no armazenamento local, histórico de versões e espelho opcional no disco via relay.
editor
Realce de sintaxe próprio, sugestões, diagnósticos, formatação e navegação entre símbolos.
preview
Monta a árvore de arquivos em endereço temporário e injeta no iframe, capturando console, erros e requisições.
build
Perfis de compilação, adaptadores de linguagem e leitura de diagnósticos.
relay
Processo local que executa comandos de verdade e devolve a saída para a IDE.
agentes
Servidor MCP que expõe leitura, escrita, testes visuais e coordenação entre vários agentes.
estúdio 3D
Blepse 3D, o modelador que abre em aba própria e devolve os assets direto no projeto.

Na prática, isso significa que um problema quase sempre pertence a uma camada. Um arquivo que não salva é sincronização. Um preview em branco raramente é o editor. A categoria Solução de problemas usa essa mesma divisão para separar sintomas.

Convenções usadas aqui

  • Mod significa Ctrl no Windows e Linux e Cmd no macOS.
  • Caminhos de arquivo aparecem como src/app.js, sempre relativos à raiz do projeto e sem barra inicial.
  • Quando o texto diz "o relay", trata-se do processo local que a IDE usa para tocar no disco e rodar comandos.
  • Recursos marcados como estimativa ou em desenvolvimento podem mudar de forma antes de chegar na versão estável.
Como chegar aqui de dentro da IDE

Na barra superior, o botão Ajuda fica à esquerda de Importar. Ele abre esta documentação e também o formulário de relato de bug.

Limites que vale conhecer antes

  • O projeto é guardado pelo navegador, por origem. Trocar de navegador ou limpar dados do site significa começar de um projeto vazio, por isso exporte com frequência.
  • Terminal, instalação de pacotes e dev server exigem o relay ligado na sua máquina. Sem ele a IDE continua funcionando, mas fica limitada ao preview interno.
  • Arquivos muito grandes entram em modo reduzido no editor para não travar a rolagem. Os números exatos estão em Editor de código.
