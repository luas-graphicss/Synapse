Extensões / Primeiros passos com extensões

Sua primeira extensão em 5 minutos

Da pasta vazia até um comando na paleta, passando pelo assistente de criação, o Extension Development Host e o primeiro teste. Nenhuma ferramenta fora do navegador.

revisado em 15/09/2026 leitura 6 min público: dev iniciante

O que é uma extensão aqui

Uma extensão é uma pasta com dois arquivos mínimos: synapse-extension.json (o manifesto, que declara identidade, permissões e contribuições) e um arquivo JavaScript principal que exporta activate(context). Ela roda em um Web Worker isolado e conversa com a IDE pela API synapse.*.

Você não precisa de Node, bundler nem terminal. A própria IDE cria o esqueleto, executa, recarrega, testa e empacota.

1. Gerar o esqueleto

  1. Abra a paleta de comandos (Ctrl+K ou F1).
  2. Execute Extensões: Criar nova extensão….
  3. Escolha o tipo Comando, informe um nome (ex.: Contador de linhas) e um publisher (seu apelido).
  4. Confirme. A IDE cria a pasta extensoes/contador-de-linhas/ dentro do projeto atual (ou um projeto novo, se você preferir) com manifesto, código, README, CHANGELOG, um teste e o synapse.d.ts para IntelliSense.
Tipos disponíveis Comando, Linguagem (gramática + snippets), Tema, Webview (painel HTML) e Formatador. Todos compartilham o mesmo layout de pasta; só mudam o manifesto e o código inicial.

2. Executar no Extension Development Host

Execute Extensões: Abrir Extension Development Host. O painel lista as extensões em desenvolvimento do projeto atual. Se a lista estiver vazia, clique em Executar pasta… e aceite a pasta sugerida.

Quando a extensão ativa, você vê:

  • status active e o tempo de ativação em milissegundos;
  • a aba Console com tudo que a extensão escreveu por OutputChannel ou console.log;
  • a aba Inspetor com comandos registrados, permissões, eventos de ativação e uma tabela comparando o que o manifesto declara com o que está de fato em execução.

Ligue Auto-recarregar. A partir daí qualquer edição em um arquivo da pasta da extensão recarrega o worker em até 1,5 s, sem perder o painel aberto.

3. Ver o comando funcionando

O template registra um comando (contador-de-linhas.executar). Abra a paleta, procure pelo título do comando e execute. O template padrão mostra uma mensagem com o total de linhas do editor ativo. No Inspetor você também pode executar qualquer comando direto pelo botão Executar. 

function activate(context) {
	const comando = synapse.commands.registerCommand('contador-de-linhas.executar', async () => {
		const editor = synapse.window.activeTextEditor;
		if (!editor) return synapse.window.showWarningMessage('Abra um arquivo primeiro.');
		synapse.window.showInformationMessage(`${editor.document.lineCount} linha(s).`);
	});
	context.subscriptions.push(comando);
}
module.exports = { activate };

4. Rodar o primeiro teste

A pasta test/ já contém extension.test.js. Testes rodam dentro do worker da extensão, com acesso à mesma API synapse.*, por isso podem executar comandos reais e inspecionar o resultado. 

const { describe, it, expect } = synapse.test;

describe('contador de linhas', () => {
	it('registra o comando', async () => {
		const comandos = await synapse.commands.getCommands();
		expect(comandos).toContain('contador-de-linhas.executar');
	});
});

No Extension Development Host clique em Rodar testes. O relatório aparece na aba Testes com tempo por caso e stack de falha quando houver. O mesmo relatório está disponível pela paleta em Extensões: Executar testes de extensão.

5. Empacotar

Quando estiver satisfeito, Extensões: Empacotar (.sx) gera o pacote instalável e valida o manifesto de novo. Veja o guia de publicação para versionamento, CHANGELOG e o fluxo automatizado com GitHub Actions que o assistente já deixou pronto.

Próximos passos

  • Manifesto e permissões: tudo que synapse-extension.json aceita.
  • Referência da API: cada função de synapse.*, gerada do arquivo de tipos.
  • Webviews: painéis com HTML próprio, CSP e troca de mensagens.
  • Linguagens: gramáticas, snippets, providers de completion e diagnósticos.

Travou em algum passo? Abra o Extension Development Host: o console mostra exatamente onde a ativação parou.
