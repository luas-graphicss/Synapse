Build e compilador

O painel de build cobre dois cenários diferentes: gerar a versão final do projeto web e compilar código nativo para rodar dentro do navegador. Os dois usam o mesmo log e a mesma lista de diagnósticos.

revisado em 09/09/2026 leitura 10 min público: dev

Abrindo o painel

Mod+Alt+B abre e fecha o painel. Ele tem três partes: seleção de perfil no topo, log no centro e diagnósticos na base.

Perfis de build

Um perfil descreve o que compilar, com quais opções e onde colocar a saída. Trocar de perfil não apaga o resultado do anterior.

Campo Para que serve
Entrada Arquivo ou lista de arquivos que iniciam a compilação.
Saída Pasta que recebe os artefatos gerados.
Otimização Nível aplicado pelo adaptador, entre depuração e release.
Definições Valores injetados na compilação, como flags de recurso.

Adaptadores

Cada tipo de projeto tem um adaptador que traduz o perfil em comandos concretos. O adaptador também sabe interpretar a saída bruta e transformar em diagnósticos clicáveis.

web
Empacota HTML, CSS e módulos ES do projeto, sem depender do relay.
nativo em wasm
Compila fontes C e C++ para WebAssembly, com interface WASI para chamadas de sistema.
cmake
Lê a árvore do projeto CMake, gera a configuração e executa o alvo escolhido.
comando livre
Executa um script do projeto pelo relay e mostra a saída no mesmo log.
Requisito

Adaptadores que chamam ferramentas de sistema precisam do relay ligado e da permissão de terminal marcada. Sem isso o build para na etapa de preparação com aviso de ambiente.

Lendo o log

O log segue sempre a mesma ordem, o que facilita achar onde parou:

preparando ambiente
resolvendo entradas
compilando
escrevendo saída
concluído em 1.8s

Se a falha aparece em "resolvendo entradas", o problema é caminho de arquivo. Em "compilando", é código. Em "escrevendo saída", é permissão ou pasta ocupada.

Diagnósticos

Cada diagnóstico traz arquivo, linha, coluna e mensagem original da ferramenta. Clicar abre o arquivo na posição exata. A lista mantém a ordem em que a ferramenta reportou, porque o primeiro erro costuma explicar os seguintes.

  • Erro interrompe o build.
  • Aviso não interrompe, mas entra no histórico daquela execução.
  • Mensagem sem arquivo associado aparece só no log, geralmente vinda da própria ferramenta.

Compilação de C e C++ para o navegador

O alvo WebAssembly serve para levar bibliotecas existentes para dentro do preview. A saída é um módulo carregável mais um arquivo de ligação em JavaScript.

Pontos que costumam gerar dúvida:

  • Acesso a arquivos passa pela camada WASI, que enxerga apenas o projeto, não o disco todo.
  • Threads dependem de recursos que o navegador pode ter desligado por segurança.
  • Tempo de build cresce rápido com o número de unidades de compilação. Use perfis separados para depuração e release.

Depois do build

Os artefatos aparecem no explorador junto com o resto do projeto e entram no zip de exportação. Se você não quer versionar a pasta de saída, mantenha ela fora do que você envia para outros lugares.

Build falhando sem mensagem clara? Cole o log inteiro no relato, ele é a parte mais útil.
